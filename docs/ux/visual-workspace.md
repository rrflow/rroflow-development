# The visual workspace

Implementation: `codex/visual-workspace`, building on the existing captured-turn,
signal and source-health APIs. This note describes the interface increment;
it is not evidence of Texas activation or a functioning hosted account flow.

## The experience the owner asked for

A person should understand what deserves a closer look without knowing what an
ingest pipeline, span or classifier is. The owner called the visual direction
"custom flat vector 2.0": fast, authored vector art, friendly navigation and
progressive detail, with contextual help and A2UI components and triggers.

The workspace now uses an evidence-derived headline and a next-action card.
The headline counts received signal matches, not failures or unique turns. The
card prefers an unreviewed finding in the newest 100 received turns, joins its
exact revision to saved reviews, and opens that turn's Signals tab. If review
history is unavailable, it does not call the finding unreviewed. Empty workspaces
offer a connection step; absence of findings never becomes an all-clear.

The signal library preserves built-ins, groups, search, preview-before-save and
pause controls. Source history remains distinct from collector reporting health.
The connection dialog first asks where the agent runs, then explains the next
step. Installation commands and development-build availability sit behind an
explicit disclosure. This guide does not silently install anything or provision
an account. SDK support is instrumented-call capture, not subscription history.

## Authored visual system

`dashboard.css` owns semantic surface, text, accent, border and illustration-area
colors, mapped separately for light and dark appearance. Components consume those
roles. `dashboard.html` owns an inline SVG symbol set and three small illustrative
scenes: capture flow, a signal lens and a source connection. Illustrations have
fixed palettes, use no external images or fonts, and are hidden from assistive
technology because the adjacent text carries their meaning. They are conceptual
art, never diagrams claiming a particular source is connected.

The interface uses warm paper, graphite, sage, lime, lilac and apricot; rounded
surfaces; restrained offset depth in vector art; and a consistent stroke icon
set. Mobile reduces the hero artwork so the next action remains visible. Motion
is limited to short nonessential transitions and respects reduced-motion settings.
The total HTML/CSS/JS shell is tested below 150 KiB raw and 40 KiB when gzip-sized.
The gzip check is a size benchmark, not a claim that the server compresses responses.
Research text is fetched only when its destination is opened.

Authored files are HTML, CSS, dashboard JavaScript, the A2UI adapter and this note.
`research.json` remains generated by `scripts/index-research.mjs`; never edit it by
hand. No token compiler, UI framework, external font or art runtime was added.

## Controlled A2UI interactions

The authority is Shippin's `contracts/a2ui/v1/` at umbrella revision `e96d6f8`,
schema `shippin.a2ui.v1`. The product owns a narrow renderer in
`dashboard-a2ui.js`, catalog `rroflow.workspace.v1`, surface `rroflow.workspace`.
There is no filesystem import from the umbrella repository.

Registered targets:

| Target | Accepted actions | Effect |
| --- | --- | --- |
| `workspace.views` | `view.select` | Select one of ten authored workspace routes |
| `workspace.guide` | `coachmark.show`, `focus.set` | Open plain-text help or focus the guide control |

Local UI triggers produce ordered envelopes. The renderer checks exact object
fields, actor, surface, IDs, action values and target allowlists. It rejects
replays and out-of-order mutations without applying them. Text is assigned with
`textContent`. No envelope can invoke JavaScript, inject markup, navigate to an
arbitrary URL, select arbitrary DOM, save a signal or submit a verdict.

This is a local-operator adapter, not a remote provider-agent transport or a
general model-generated component renderer. Provider-agent actors are rejected.
Authenticated transport, per-action permissions and a broader component catalog
need their own implementation and validation before external agents can drive UI.
Session-local adapter state is cleared at logout.

## Interaction and verification

Help is available from the workspace guide, source and library introductions,
and next-action explanations. Hover/focus tooltips also open full explanations
on click or Enter, including touch. Escape dismisses tooltips. Native modal dialogs
contain focus, close with Escape, and return focus to their opener. Existing turn
details retain keyboard tabs and advanced source/tool/revision detail.

`scripts/test-dashboard.mjs` covers account clearing, evidence identity, unavailable
reviews, empty states, bounded asset size, A2UI validation/replay/order and guidance
actions. `scripts/dashboard-ui` runs the actual compiled service with temporary
fixture data on desktop and phone, checks reflow and automatic WCAG issues, and
captures overview, library, evidence, connection, help and dark appearance images.
Screenshots are explicitly fixture evidence, never the owner's activity.

Automatic accessibility checks and developer visual review do not substitute for
the owner's judgment of this visual direction or for assistive-technology testing.
Automatic datasets, training, paid-tier enforcement and Texas activation remain
separate acceptance work.
